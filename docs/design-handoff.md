# 設計引き継ぎ

## 目的

OpenCode等でコード解析結果をHTMLとして生成し、理解・設計・根拠・変更判断を後から再利用する。
さらにセッションログにも同じ認知モデルを適用し、知識・判断・未解決事項を次回に渡す。
完成HTMLを持ち込めない環境でも、意味構造をInstructionsだけから再構築できることが到達点。

## 議論をたどるための順序

| 段階 | 問題 | 到達した判断 | 出典 |
|---|---|---|---|
| 初期 | 関数一覧だけでは仕組みを理解できない | 理解セル → 外部契約 → 内部実現というPattern Cを保持 | S01 |
| Multi-View化 | 各形式で独立解析すると食い違う | 共通解析モデルからDOCUMENT 3種とVIEW 4種へ投影 | S02 |
| V2調整 | MDNが重く、K8sが単なる概要だった | Definitionは縮小、ConceptはWhy・Mental Model・Lifecycleまで深化 | S03 |
| V3 | 推論・改善案・変更影響が事実に見える | 4分類、IN/OUT、折りたたみ、Relation / Impact、Canonical JSON | S04–S05 |
| セッション転用 | 会話を短縮するだけでは判断が失われる | Decision LedgerとHandoffを第一級にする | S06 |
| 参照なし生成 | 完成V3を入力にできない | 認知モデル・schema・表示契約・検証規則を文章化 | S07 |
| Agent Builder用 | 複数仕様ファイルを渡しにくい | 一つのInstructionsへ統合 | S08 |
| リポジトリ保存 | 会話中の結論だけでは次回理由を再発見する | 成果物に加え判断履歴と生成規則をcommitして再利用 | S09 |

出典S01–S09の本文・Turn IDは[出典](sources/design-discussion.md)にある。
ここで保存する判断履歴は発言で確認できる設計理由であり、モデルの非公開の思考過程を再現するものではない。

## 変更しない中核

- 解析が先、HTMLは後。Evidence → Canonical → 整合性確認 → DOCUMENT → VIEW。
- FACT / INFERENCE / PROPOSAL / UNKNOWNを混ぜない。
- 未確認・該当なし・調査範囲で見つからない、を区別する。
- 理解セルは読者の到達目標で分ける。関数数で分けない。必要な説明の再掲を認める。
- 全表示は同じCanonicalから生成する。表示だけ直して矛盾を隠さない。
- 接続関係と変更影響予測は別。設計意図と説明のためのMental Modelも別。
- 完成見本の画素単位の再現は目標にしない。
